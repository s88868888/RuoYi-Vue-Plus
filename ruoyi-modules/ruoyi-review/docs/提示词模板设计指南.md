# 提示词模板设计指南

> 关注本文件后，你能：①写出新业务类型的模板，②理解每个占位符的语义，③知道何时用增强约束。

ruoyi-review 是**通用 AI 审核引擎**：不绑定具体业务（公司/合同/协议都能审）、不绑定具体模型（DashScope/Ollama 切换无需改代码）、不绑定具体 OCR（PaddleOCR/Qwen-VL OCR 切换无需改代码）。新业务类型接入只需要做两件事：**①新建模板，②外部系统传 `taskType`**，**零代码改动**。

---

## 一、模板由什么组成

```
review_prompt_template
├─ name           显示名（仅人看）
├─ type           taskType 唯一标识，外部传过来路由用
├─ system_prompt  系统提示词（含占位符）
├─ user_prompt    用户提示词（含占位符）
├─ output_format  输出 JSON 模板（含占位符）
├─ model_config_id  这个模板用什么 chat 模型 (purpose=chat)
└─ ocr_config_id    这个模板用什么 OCR (purpose=ocr，仅扫描件PDF会用到)
```

**关键概念**：模板 = prompt + chat模型 + ocr模型 的绑定。换业务/换模型/换OCR 都只需要在 DB 里调，不动代码。

## 二、占位符全集

ReviewAgent 会在调用 AI 前做字符串替换，把占位符填充成实际值。

### 2.1 通用占位符（所有模板都建议用）

| 占位符 | 出现在 | 必需？ | 替换为 |
|-------|--------|-------|--------|
| `{rules}` | system_prompt | ✅ | 该任务关联的所有 `review_standard_rule`，编号 + 字段 + 严重度 + 描述 |
| `{output_format}` | system_prompt | ✅ | 模板的 `output_format` 字段（要求 AI 输出的 JSON 结构） |
| `{form_data}` | user_prompt | ⚠️ 表单类必加 | `ReviewTask.form_snapshot`（外部系统传的表单 JSON） |
| `{knowledge_context}` | system_prompt | 可选 | RAG 检索到的相似审核案例；没规则关联知识库则为空串 |

### 2.2 增强占位符（治本地小模型不听话用）

> 仅当本地 35B 等模型 **编造字段名 / 漏返字段 / 长度失控** 时才上。云端 qwen-long/qwen-plus 大多不需要。

| 占位符 | 替换为 | 何时用 |
|-------|--------|-------|
| `{rule_count}` | 数字，本任务规则总数 | 模型偷懒少返 items，让它「必须返回 N 条」 |
| `{field_whitelist}` | 编号 + 字段名 列表，每行一个 | 模型编造 `xxx1/xxx2` 这种带后缀的字段名时 |

**这两个占位符是可选的，不写不替换不报错。** 模板 1（公司）和 2（合同）就没用，模板 1001（补偿协议+本地 35B）才用。

### 2.3 已经废弃 / 不推荐

| 占位符 | 状态 | 替代 |
|-------|------|------|
| `{rule_count}/{field_whitelist}` 写在云端模板 | 不推荐 | 云端模型已经听话，加约束反而限制发挥 |

## 三、output_format 字段语义

模板里 `output_format` 字段是 AI 必须返回的 JSON 结构。ReviewAgent 不硬解析内部字段（除了 `items` 数组本身），所以**字段名可以按业务自由扩展**。

### 3.1 推荐结构

```json
{
  "pass_status": "passed | partial | failed | need_review",
  "score": 0,
  "summary": "整体审核结论一句话",
  "items": [
    {
      "rule_id": 1,
      "field_name": "company_name",
      "match_status": "matched | mismatched | not_found | uncertain | missing",
      "severity": "must | should | may",
      "form_value": "表单里的值",
      "extracted_value": "AI从材料里提取的值",
      "expected_value": "规则要求的值",
      "comment": "判定理由",
      "suggestion": "整改建议",
      "confidence": 90,
      "location": "材料定位（如：第3页签字栏）"
    }
  ]
}
```

### 3.2 match_status 取值约定

| 值 | 含义 |
|----|------|
| `matched` | 表单/材料一致，规则通过 |
| `mismatched` | 表单/材料**不一致**（注意：金额大小写差异、全半角差异都算不一致） |
| `not_found` | 材料里找不到该字段对应内容 |
| `uncertain` | 图片模糊/字迹不清，无法判断 |
| `missing` | 提交的材料类型错了（要营业执照传成安全许可证），不能强行判定通过 |

> **`matched` 这个值不是写死在代码里的**，是模板自己约定的。换业务想改成 `pass / fail / unclear` 也行，只要模板和前端展示对齐就行。

### 3.3 字段命名风格

- 用 **snake_case**（field_name / form_value / extracted_value）
- 数值字段用 number 不用 string（confidence:90，不是 "90"）
- 详见 `ReviewAgent.parseAiResponse` 的解析逻辑（不要破坏 `items` 数组结构）

## 四、新业务接入实操

### 场景：表单 vs PDF 文档对比（用户问的新例子）

外部系统的需求：用户填了表单，又上传了一份 PDF 文档，要 AI 对比两者一致性。

**步骤**：

1. 进「AI模型配置」菜单
   - 已有 `dashscope-qwen-long`（云端文档模型）就用它，没有就新建
   - OCR 用 `local-paddleocr`（如果 PDF 可能是扫描件）
2. 进「提示词模板」菜单 → 新增
   - **模板名称**：表单PDF对比审核
   - **类型编码**：`form_pdf_compare`（外部传 `taskType=form_pdf_compare`）
   - **AI模型配置**：选 `dashscope-qwen-long`
   - **OCR模型配置**：选 `local-paddleocr`（不选也行，会走全局兜底）
   - **系统提示词**：
     ```
     你是审核专家。任务：对比用户提交的【表单数据】和【PDF文档】内容是否一致。

     审核规则：
     {rules}

     参考经验：
     {knowledge_context}

     输出格式：
     {output_format}
     ```
   - **用户提示词**：
     ```
     ## 表单数据
     {form_data}

     ## PDF文档
     请仔细识别附件中的PDF内容，与上述表单逐字段对比。
     ```
   - **输出格式**：复用模板 1 的 output_format 即可
3. 在「规范库」里挂相关规则到这个 type
4. 外部系统调：
   ```bash
   curl -X POST http://localhost:8081/review/task/createAndExecute \
     -H "Content-Type: application/json" \
     -d '{
       "taskName": "XX项目审核",
       "taskType": "form_pdf_compare",
       "sourceId": "xxx-uuid",
       "sourceType": "biz",
       "callbackUrl": "http://yoursys/callback",
       "formSnapshot": "{\"name\":\"xxx\",\"amount\":\"100\"}",
       "files": [
         {"fileName":"合同.pdf","fileType":"pdf","filePath":"http://oss/合同.pdf"}
       ]
     }'
   ```

**完事**。**零代码改动**。

## 五、模板调试技巧

### 5.1 AI 偷懒只返回 3 条规则但任务有 15 条
→ system_prompt 里加 `{rule_count}` 占位符，并显式说「items 长度必须等于 {rule_count}」

### 5.2 AI 编造字段名（你的规则字段叫 `address`，AI 返回了 `bus_address1/2/3`）
→ system_prompt 里加 `{field_whitelist}` 占位符，并显式说「field_name 只能来自下面列表」

### 5.3 输出 JSON 经常截断在中间
→ 三层防御：
- 模板层：`{output_format}` 里别要求过长字段（description 限 150 字以内）
- 引擎层：在「AI模型配置」编辑界面，把 `num_predict` 调到 8000+
- 解析层：ReviewAgent 已有 `salvageTruncatedJson` 兜底解析

### 5.4 表单字段不对应规则
→ 模板的 user_prompt 里 `{form_data}` 会原样塞表单 JSON，AI 自己理解。规则字段名建议和表单 key 对齐。

### 5.5 扫描件 OCR 错误率高
→ 在「AI模型配置」新建一条云端 `qwen-vl-ocr`，模板里把 OCR 配置改过去。本地 PaddleOCR 印章/手写一般，云端 vl 模型识别更全。

## 六、目前架构的边界（什么时候必须改代码）

| 场景 | 是否改代码 | 原因 |
|-----|-----------|------|
| 新业务类型（表单+PDF/表单+图/PDF+PDF/单PDF） | ❌ 不用 | 模板就行 |
| 切换 AI 模型（DashScope→本地/换 DeepSeek） | ❌ 不用 | 在「AI模型配置」改 |
| 切换 OCR（PaddleOCR→云端 VL） | ❌ 不用 | 在「AI模型配置」改 |
| 加新模型厂商（如 Moonshot/智谱） | ✅ 要改 | AiChatService 加 provider 分支 |
| 加新 OCR 厂商（百度OCR/腾讯OCR） | ✅ 要改 | 加 OcrProvider 实现类 + 在 DB 里加配置 |
| **图片+PDF 混合输入**（一个任务里既有图又有 PDF） | ✅ 要改 | 当前 ReviewAgent.callAi 是文档/视觉路二选一 |
| Excel/Word 解析 | ✅ 要改 | 现在只支持 PDF 和图片 |
| 视频/音频 | ✅ 要改 | 完全没接入 |

> 用户问的「表单+PDF」属于第一档，**完全不用改代码**。
