# 外部系统接入指南

ruoyi-review 是通用的 AI 审核系统，外部业务系统通过 4 个 HTTP 接口完成接入：
**创建任务 → AI 异步审核 → Webhook 回调结果 → 验签**。

> 本文示例用 `http://localhost:8081` 作为审核系统地址，按实际环境替换。

---

## 一、整体流程

```
外部业务系统                   ruoyi-review                  AI / OCR
   │                              │                            │
   │ 1. POST /review/task/        │                            │
   │   createAndExecute           │                            │
   │ ───────────────────────────→ │                            │
   │                              │ 2. 异步 OCR + AI 调用       │
   │                              │ ──────────────────────────→ │
   │ ← taskId                     │                            │
   │                              │ ←──────────── result        │
   │                              │                            │
   │ ← 3. POST callbackUrl (HMAC) │                            │
   │ ←─────────────────────────── │                            │
   │ 4. 校验签名 → 落库本地结果   │                            │
   │                              │                            │
   │ 200 OK                       │                            │
   │ ───────────────────────────→ │                            │
```

关键约定：
- 审核系统**只跑 AI**，不存业务数据。结果通过 webhook 推回外部系统，由外部系统决定怎么用。
- 外部系统必须传 `callbackUrl`，否则审核完成后不通知（任务状态可在审核系统查到，但外部不会被推送）。
- 同一个 `(sourceId, sourceType)` 复审会 **UPDATE 原行 + version+1**，不会产生新行。

---

## 二、接入清单（外部系统侧需要做的）

1. 暴露一个回调端点（例：`POST /api/review-callback`），跳过登录鉴权和 CSRF
2. 共享 webhook secret（找审核系统管理员获取）
3. 调 `POST /review/task/createAndExecute` 创建任务
4. 在回调端点验证 HMAC 签名，落库结果

---

## 三、API 详细说明

### 3.1 创建并执行审核（推荐）

`POST /review/task/createAndExecute`

请求体：
```json
{
  "taskName": "X公司入会资料审核-2026-05-22",
  "taskType": "company_info",
  "sourceId": "uuid-xxx-yyy",
  "sourceType": "company",
  "standardIds": [101, 102],
  "callbackUrl": "http://外部系统域名/api/review-callback",
  "formSnapshot": "{\"name\":\"xx公司\",\"contact\":\"...\"}",
  "files": [
    {
      "fileName": "营业执照.pdf",
      "fileType": "pdf",
      "filePath": "http://oss.example.com/abc/营业执照.pdf",
      "fileSize": 102400
    }
  ]
}
```

字段说明：

| 字段 | 必填 | 说明 |
|------|------|------|
| taskName | ✅ | 任务名称，用于审核系统列表展示 |
| taskType | ✅ | 任务类型，决定走哪个提示词模板，没匹配的回退 `general` |
| sourceId | ✅ | 外部业务主键，**字符串**类型（兼容 UUID） |
| sourceType | ✅ | 外部业务系统标识（如 `company`/`bid`/`procurement`） |
| standardIds | ⚠️ | 关联的审核标准 ID 列表，决定用哪些规则审核；为空则模板里默认规则 |
| callbackUrl | ⚠️ | 不传则审核完成后**不通知**，但任务和结果在审核系统里可查 |
| formSnapshot | - | 表单 JSON 快照，会作为 `{form_data}` 传给 AI |
| files | - | 附件列表，`filePath` 优先用 `http(s)://` 完整 URL |

返回：
```json
{
  "code": 200,
  "msg": "操作成功",
  "data": 1812345  // taskId
}
```

> 旧入口 `POST /review/task` 仍可用，但需要再调一次 `POST /review/task/{id}/execute` 才会触发审核。

### 3.2 文件 filePath 规则

- **优先传 `http://` 或 `https://` 完整 URL**，审核系统直接下载
- 传相对路径（如 `upload/abc.pdf`）时，审核系统按 `review.external.file-base-url` 配置拼接
- `fileType` 必须是真实扩展名（`pdf` / `docx` / `png` / `jpg`），影响路由（图片走视觉模型、文档走文本模型）

### 3.3 查询任务状态（可选）

`GET /review/task/{id}` — 详情，含 status / passStatus / score / aiSummary / 关联文件

`GET /review/task/{id}/results` — 审核明细，每条规则的判定

> 标准用法是**等回调推送结果**，不要轮询 GET 接口，会拖死审核系统的 DB。

## 四、Webhook 回调

任务执行完成（成功或失败）后，审核系统会向 `callbackUrl` 发起 `POST` 请求。

### 4.1 请求头

| Header | 说明 |
|--------|------|
| `Content-Type` | `application/json` |
| `X-Review-Timestamp` | 时间戳（毫秒），防重放，外部系统应检查 5 分钟内有效 |
| `X-Review-Signature` | HMAC-SHA256 签名，hex 编码 |

### 4.2 签名规则

```
sign_str = timestamp + "\n" + raw_body
signature = HEX(HMAC_SHA256(secret, sign_str))
```

### 4.3 请求体

```json
{
  "taskId": 1812345,
  "sourceId": "uuid-xxx-yyy",
  "sourceType": "company",
  "version": 1,
  "status": "completed",          // completed / failed
  "passStatus": "passed",         // passed / failed / partial / null
  "score": 92,
  "aiModel": "qwen3.6:35b-a3b-q4_K_M",
  "aiSummary": "整体合规，发现2处需补充...",
  "totalRules": 15,
  "passCount": 13,
  "errorCount": 1,
  "warningCount": 1,
  "items": [
    {
      "ruleId": 5001,
      "fieldName": "company_address",
      "matchStatus": "fail",
      "severity": "error",
      "extractedValue": "...",
      "expectedValue": "...",
      "comment": "地址与营业执照不一致"
    }
  ]
}
```

### 4.4 重试机制

调用失败（HTTP 非 2xx 或 IO 异常）会触发重试，**最多 3 次**：
- 第 1 次失败后等 2s 重试
- 第 2 次失败后等 5s 重试
- 第 3 次失败后等 10s 重试
- 仍失败则放弃，记入审核系统日志

> **注意**：外部系统回调端点必须返回 HTTP 2xx 表示已收。返回 4xx/5xx 会触发重试，5 分钟内可能收到 4 次相同回调，业务方应做幂等（按 `taskId+version` 去重）。

## 五、外部系统侧验签 demo

### Java

```java
@PostMapping("/api/review-callback")
public ResponseEntity<String> reviewCallback(
    @RequestBody String rawBody,
    @RequestHeader("X-Review-Timestamp") String timestamp,
    @RequestHeader("X-Review-Signature") String signature) {

    // 1. 时效校验（5 分钟）
    long now = System.currentTimeMillis();
    long ts = Long.parseLong(timestamp);
    if (Math.abs(now - ts) > 5 * 60 * 1000L) {
        return ResponseEntity.status(401).body("timestamp expired");
    }

    // 2. 签名校验
    String expected = hmacSha256(secret, timestamp + "\n" + rawBody);
    if (!constantTimeEquals(expected, signature)) {
        return ResponseEntity.status(401).body("bad signature");
    }

    // 3. 业务处理（必须幂等！）
    JSONObject payload = JSON.parseObject(rawBody);
    Long taskId = payload.getLong("taskId");
    Integer version = payload.getInteger("version");
    // ... 按 (taskId, version) 去重落库

    return ResponseEntity.ok("ok");
}

private String hmacSha256(String secret, String message) throws Exception {
    Mac mac = Mac.getInstance("HmacSHA256");
    mac.init(new SecretKeySpec(secret.getBytes(StandardCharsets.UTF_8), "HmacSHA256"));
    byte[] raw = mac.doFinal(message.getBytes(StandardCharsets.UTF_8));
    StringBuilder sb = new StringBuilder();
    for (byte b : raw) sb.append(String.format("%02x", b));
    return sb.toString();
}
```

### Python

```python
import hmac, hashlib, time

def verify(raw_body: bytes, timestamp: str, signature: str, secret: str) -> bool:
    if abs(int(time.time() * 1000) - int(timestamp)) > 5 * 60 * 1000:
        return False
    msg = f"{timestamp}\n{raw_body.decode('utf-8')}".encode('utf-8')
    expected = hmac.new(secret.encode('utf-8'), msg, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)
```

## 七、错误码与排查

| 现象 | 原因 | 对策 |
|------|------|------|
| 创建任务返回 200 但状态一直 RUNNING | autoExecute=false 但调用方没调 execute | 用 `createAndExecute` 端点；或单独调 `POST /task/{id}/execute` |
| 收到回调但签名验证失败 | secret 不一致 / 验签时用了 parse 后的 JSON 而不是 raw body | 验签**必须用原始 body**，不能 parse 后再序列化 |
| 收不到回调 | callbackUrl 不可达 / 返回非 2xx | 看审核系统日志「[ReviewAgent] 回调失败」；用 `R.fail` 返回会被识别为成功，必须用 ResponseEntity.status(401) |
| 同一任务收到 4 次回调 | 业务端首次返回非 2xx 触发重试 | 业务端按 `(taskId, version)` 做幂等 |
| filePath 下载 404 | 相对路径但 `review.external.file-base-url` 没配 | 改为传完整 URL，或在 yml 配置 base url |
| 审核结果 items 字段全空 | 提示词模板没传 `{rules}` / `{output_format}` 占位符 | 检查模板内容必须含这两个占位符 |
